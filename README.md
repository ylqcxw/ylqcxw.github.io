# 卡农社区实时面板

浏览器直连采集的社区数据面板。**没有后端，不需要开着电脑** —— 页面托管在 GitHub Pages 上，
手机电脑随时随地打开就能用，数据存在你自己的浏览器里。

当前版本 **v1.0.3**，变更记录见 [CHANGELOG.md](CHANGELOG.md)。

## 怎么用

打开页面就自己开始采，一般不用手动点。分三步走：

1. **先出内容**：拉第 1～3 页，几秒内列表就有东西看。
2. **再补全 24 小时**：接着从第 4 页往后翻，翻到回溯满 24 小时收工。
   一天约 1600～3000 帖，`step=200` 大概 6～10 个请求、30 秒左右。
   补全过程里每隔一会儿会插空回来刷一次新帖，首页不会僵住。
3. **之后自动刷新**：默认 **15 秒一轮**，只翻前几页（新帖都在最前面），稳态下两三个请求。

几个要点：

- **只看最近 24 小时**。窗口固定，不提供切换 —— 接口回不去 7 天，硬翻也没用。
- **自动刷新只在第 1 页跑**。翻到第 2 页往后是在看旧帖，刷新会重排列表把内容挤走，
  所以此时暂停（按钮显示"暂停"，下面有说明），**点回第 1 页会立刻补一轮**。
  点「自动」可在 15s / 60s / 5min / 关之间切换。
- **库不会变大**：超过 48 小时的帖子每次采集后自动清掉，本地库恒定几百 KB。
- **数据存在本地**（浏览器 IndexedDB）。换浏览器、清缓存、换设备都会丢，
  换之前用「导出 JSON」备份，到新设备「导入」即可。
- 点「发帖密度」的柱子会显示它代表的时段（手机上没有悬停，靠点击）。
- 顶部选的**数据来源会被记住**（存在 localStorage），下次打开还是那一端。
- 帖子多时有八九十页，分页器是「‹ 页码框 / N 页 › 跳转」，想看第几页直接输入。
- 个人资料卡底部可以**换另一端去查** —— 有人锁了主页，换一端往往就能看到。

顶部可切「卡农社区」（my 端）和「卡农APP」（fen 端）。
两端是同一论坛的两个频道入口，帖子 id 通用、库共享，差别只在覆盖的板块范围。

## 部署到 GitHub Pages

1. 在 GitHub 新建一个仓库（例如 `kanong-dashboard`），**Public**。
2. 把这个目录里的 `index.html`、`.nojekyll` 和本文件上传到仓库根目录。
3. 进仓库 **Settings → Pages**，Source 选 `Deploy from a branch`，
   Branch 选 `main`、目录选 `/ (root)`，保存。
4. 等 1～2 分钟，访问 `https://你的用户名.github.io/kanong-dashboard/` 即可。

最快的方式是直接把 `index.html` 拖进 GitHub 网页端的仓库上传框，
不用装 Git、不用敲命令。

### 命令行方式

```bash
git init
git add index.html .nojekyll README.md
git commit -m "卡农实时面板"
git branch -M main
git remote add origin https://github.com/你的用户名/kanong-dashboard.git
git push -u origin main
```

之后照第 3 步开 Pages。

## 关于隐私

- 页面**不上传任何数据**，也没有后端、没有统计脚本。
- 采集请求由**你的网络直接发往卡农服务器**，不经过任何中间节点。
- 本地库只存在你自己浏览器里。别人打开这个网址，看到的是他自己的空库。
- 注意：仓库是公开的，任何拿到网址的人都能使用这个页面。

## 技术说明

- 数据源：`my.kanong01.com` / `fen.kanong01.com` 的 MagApp 接口，
  返回 `Access-Control-Allow-Origin: *`，所以浏览器可直连，无需代理。
- 板块 `fid`（取自列表项 `type_value`）是论坛原生 ID，两款 APP 完全一致：
  `169` 羊毛交流、`282` 羊毛专区、`285` 老哥生活。
  而 `cat_id` 是各 APP 自己的信息流频道号（my=7、fen=27）。
- 头像走 `ucenter.kanong.com/avatar.php?uid=<uid>&size=small`，两端**通用**（不像
  `userHomev3.head` 那样只对应当前端），没有防盗链，uid 不存在时返回默认图不会破图。
  列表和 Top10 直接用这个 URL，头像跟列表一起出来，不用等接口。
- 「用户组」徽章（卡仙/卡尊/卡友…）取自 `userHomev3.group_name`，与 `getUserInfo`
  里的「用户组」一致，不用多打请求；「注册天数」才需要额外请求，点开资料框时懒加载。
- 存储：库只留 48 小时（约几千条、几百 KB），每次采集自动清理过期的，不用手动维护。
- **热词已删除**：纯前端抽取的二字词没有分词能力，噪音太大，没有价值。
- 实测接口的回溯上限（2026-10-06）：

  | step | 能翻到 | 拿到 | 覆盖 |
  |---|---|---|---|
  | 100 | 50 页 | 约 5000 帖 | — |
  | 200 | 50 页 | 约 10000 帖 | **约 4.9 天**（50 个请求、3 分钟） |
  | 500 | **第 4 页就空** | 约 1500 帖 | 约 0.9 天 |

  `step` 越大反而拿得越少，所以固定用 `200`。

## 静态前端做不到的事

后端常驻版（`dashboard.py`）有一批功能，纯静态页给不了，这一版就没有做：

| 功能 | 为什么做不到 |
|---|---|
| **探测删帖** | 要定期回访已采的每条帖子看还在不在。前端做等于一次发几千个请求，而且关掉页面就停了 |
| **采集增长曲线** | 需要常驻进程按时间采样"库里有多少帖"。前端只在打开时才有一个数据点，画不出连续曲线 |
| **暂停/继续采集、下次采集倒计时** | 都是常驻服务的调度概念，没有服务端就没有 |
| **低谷期自动降频、连续失败告警** | 同上，属于后台调度 |
| **多设备共享同一份数据** | IndexedDB 按浏览器隔离，手机和电脑各攒各的。要同步就用导出/导入 |

## 已知限制

- **7 天窗口做不到**：接口最多只能回溯约 10000 帖 ≈ 5 天（而且要走满 50 个请求、约 3 分钟）。
  所以这一版固定只看 24 小时，不提供 7 天选项 —— 与其放一个点了也填不满的按钮，不如不做。
- 只有打开页面时才会采集。24 小时内的数据一次就能补齐，不用攒，但**关着电脑时没人替你采**：
  隔了一天再打开，中间那段就是空的（新帖能补上，因为它们在列表最前面）。
- 浏览器对后台标签的定时器有节流，最小化挂着可能不按点采。
- 卡农接口若变更字段或加限流，页面会显示采集失败，改一下字段映射即可恢复。
